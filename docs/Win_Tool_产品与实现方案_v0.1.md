## 1. 背景、目标与非目标

### 1.1 背景
- 〔用户确认〕要做一个 Windows 桌面工具，用于记录**待办事项**、**账号密码**、**随笔**三类内容。
- 〔事实〕参考项目 TO-DO Panel 的公开首页（https://xiaopu-ai.github.io/TO-DO-Panel/ ，2026-11-14 抓取）自述为"把灵动岛变成工作台"的**贴顶**面板，包含 6 个工作区：待办、剪贴、笔记、链接、录制、密钥；并附带 AI 完成提醒（Codex / Claude / GPT）等能力。
- 〔用户确认〕参考项目功能偏多，本工具要**更精简**；不照搬其多余功能。
- 〔用户确认〕**不希望屏幕中间出现"留海"式 UI**，并认为该元素应当可以隐藏。
- 〔用户确认〕待办完成后需**自动清理**，最好在本地以 **Markdown 留底**；随笔用于方便记笔记。

### 1.2 产品目标
用一个轻量常驻的本地桌面程序，把"记一条待办 / 查一个账号 / 写一段随笔"这三件事压缩到最少操作步骤，数据全部留在本机。

### 1.3 非目标（明确不做，见 §2.2 展开）
- 不做剪贴板历史、链接收藏、录音与转写、AI 完成提醒、多工作流看板、云同步、账号体系。
- 不做屏幕顶部居中的"灵动岛/留海"式悬浮控件。
- 不做团队协作、跨设备同步、移动端。

## 2. 功能范围

### 2.1 范围内（仅此三类）

| 模块 | 一句话定义 | 必须满足 |
| --- | --- | --- |
| 待办事项 | 记一条要做的事，勾掉即完成，完成后按规则自动清理并留 Markdown 底 | 新增 / 完成 / 自动清理 / 留底（规则见 §5） |
| 账号密码 | 记录并查看某个站点或服务的账号信息 | 字段与存储方式见 §6；**存储方式待确认** |
| 随笔 | 随手写一段文字并本地保存 | 快速记录、列表回看、本地保存（§7） |

〔用户确认〕范围严格限定为上表三类。

### 2.2 范围外（对照参考项目逐项排除）

〔事实〕下表左列为参考项目公开页面自述的功能；右列为本项目的处置。

| 参考项目功能 | 本项目处置 | 说明 |
| --- | --- | --- |
| 待办（四个可改名工作流、到期前一小时提醒） | 部分采纳，砍掉多工作流 | 只保留单一待办清单；多工作流与提前提醒不在范围内（提醒是否要，列入待确认 D4，不默认实现） |
| 剪贴（剪贴历史、图片、收藏） | 不做 | 与三类核心功能无关，且涉及全系统监听，代价大 |
| 笔记（资料库、搜索、重命名） | 部分采纳 → 即"随笔" | 只保留写入与回看，资料库式组织结构不做 |
| 链接（粘贴 URL 自动补全标题/图标/分组） | 不做 | 需联网抓取，破坏"纯本地" |
| 录制（麦克风、实时转写） | 不做 | 与三类核心功能无关 |
| 密钥（账号、密码、API Key，系统安全存储加密） | 部分采纳，**方式不照搬** | 只做"账号密码"；是否记录 API Key 不做；存储与保护方式〔待确认〕D1，不得因参考项目用了系统安全存储就默认同样实现 |
| AI 完成提醒（Codex / Claude / GPT） | 不做 | 引入外部依赖与会话监听 |
| 贴顶"灵动岛"常驻形态 | **明确不做** | 用户明确否决"留海"式 UI，见 §3 |

### 2.3 范围变更规则
任何在开发过程中冒出的新功能（标签体系、提醒、导入导出、同步、统计等），一律不直接实现，先登记到 §9 待确认清单，由用户裁决。**"顺手加一下"视为范围违规。**

## 3. 界面布局与隐藏 / 唤出

### 3.1 硬约束

- 〔用户确认〕**不得**出现屏幕中间（或屏幕顶部居中）的"留海 / 灵动岛 / 胶囊"式悬浮 UI。
- 〔用户确认〕该设计元素"应可隐藏"。

> 口径说明：本方案**根本不实现**留海式组件，因此不存在"隐藏留海"这个动作；等价需求改由"主窗口可完全隐藏、仅留系统托盘"来满足。若用户原意是"保留留海但可隐藏"，属于 D3 的一种候选，需在 D3 中明确选择，不得由开发者自行决定。

### 3.2 主界面布局〔拟议〕

常规可缩放窗口，默认约 960×620，最小 720×480，**不默认置顶**、不贴顶、不占屏幕中央无边框悬浮层。

```
┌──────────────────────────────────────────────────────────┐
│ [搜索框]                              [+ 新建]   [⚙]     │  ← 顶栏
├──────────┬───────────────────────────────────────────────┤
│ ▸ 待办    │  列表区                    │  编辑区          │
│ ▸ 账号    │  （左：条目列表）           │  （右：详情）     │
│ ▸ 随笔    │                            │                  │
│          │                            │                  │
├──────────┴────────────────────────────┴──────────────────┤
│ 状态条：条目数 / 最近一次留底时间 / 同步状态（本地）        │
└──────────────────────────────────────────────────────────┘
```

- 左侧：三项导航（待办 / 账号 / 随笔）+ 设置入口。**不设**参考项目那种 6 tab 工作区。
- 中部：当前模块的条目列表（待办为单列勾选列表；账号与随笔为标题列表）。
- 右侧：选中条目的详情/编辑器（待办为内联编辑，账号为表单，随笔为纯文本编辑区）。
- 顶栏固定：搜索 + 新建 + 设置。
- 视觉密度：单列、无卡片堆叠、无仪表盘图表。

### 3.3 常驻形态与唤出方式（D3〔待确认〕）

以下为**候选枚举，未选定**，不得作为实现依据，也不得默认采用第一项：

| 候选 | 形态 | 唤出 | 隐藏 | 备注 |
| --- | --- | --- | --- | --- |
| A | 系统托盘常驻（无可见窗口） | 全局热键 / 托盘左键 | 热键再按 / Esc / 失焦 | 最贴近"无留海"诉求 |
| B | 屏幕侧边停靠条（左或右侧边缘吸附，非顶部居中） | 鼠标触边 / 热键 | 自动收缩为窄条 | 需额外处理多显示器与全屏应用 |
| C | 纯托盘 + 手动打开窗口 | 仅托盘菜单 | 关闭窗口即隐藏到托盘 | 最简，但唤出慢 |

- 待确认项：**选择哪个候选或组合**（D3）。
- 与候选无关、可直接实现的部分〔拟议，但属实现细节，不依赖 D3〕：
  - 单实例运行：重复启动只唤起已有实例。
  - 隐藏 = 从任务栏与屏幕移除，但进程常驻托盘；**真正退出**由托盘右键菜单"退出"执行。
  - 隐藏后不得丢失未保存输入（切换/隐藏前落盘）。
  - 首次启动给出一次性的"如何唤出"提示，可关闭。

### 3.4 隐藏与恢复的行为规则〔拟议〕

1. 显示/隐藏必须是幂等切换：同一操作连按两次回到原状态。
2. 隐藏状态下不接收键盘焦点、不遮挡前台应用。
3. 若全局热键被其他程序占用，注册失败必须给出可见提示并回退到托盘菜单唤出，不得静默失效。
4. 关机/注销前保存当前编辑内容。

### 3.5 界面层不做的事
不做贴顶横幅、不做屏幕中央浮层、不做全屏遮罩、不做常驻悬浮球、不做多窗口。

## 4. 数据与本地文件

### 4.1 数据目录（路径〔待确认〕；结构〔拟议〕）

```
<数据根目录>            ← 具体路径待确认（候选：用户目录下的应用数据目录 / 用户自选目录）
├─ data.db              ← 结构化数据（待办、账号、随笔索引）
├─ archive/             ← 待办完成留底的 Markdown 文件（位置见 D2）
└─ notes/               ← 随笔的 Markdown 文件（可选，见 §7.4）
```

- 数据根目录的**确定位置**〔待确认〕，随 D2 一并裁决（留底文件位置与数据目录通常需一致，避免分处两地）。
- 目录首次启动自动创建；不可写时必须明确报错并阻塞启动，不允许"静默降级到临时目录"。
- 卸载是否保留数据：〔待确认〕（不默认删除）。

### 4.2 三类数据的关系
- 三块数据相互独立，互不引用（待办不挂随笔，账号不挂待办）。
- 统一的条目身份：每条记录有稳定 ID（创建时生成，不随标题变化），用于留底去重与编辑追踪。
- 时间：本地时区存储，落盘统一存 ISO-8601 带偏移量的字符串。

## 5. 待办事项

### 5.1 字段〔拟议〕

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| id | 是 | 系统生成，不可变 |
| 标题 | 是 | 单行，去首尾空白后不得为空 |
| 备注 | 否 | 多行纯文本 |
| 截止时间 | 否 | 日期时间；仅展示与排序用（是否提醒见 D4） |
| 创建时间 | 是 | 自动 |
| 完成时间 | 是（完成后） | 自动，完成动作发生时写入 |
| 状态 | 是 | 未完成 / 已完成（已完成项在清理前可能短暂存在） |

字段集为〔拟议〕，开发前随 D2 的"留底字段"要求做一次对齐；D2 未定时不得把字段集当作已冻结契约。

### 5.2 新增流程
1. 触发：顶栏"新建"或（若启用）快捷输入热键。
2. 只填标题即可提交（回车提交、Esc 取消）。
3. 校验：标题非空；超长截断或拒绝（上限〔待确认〕，不预设数值）。
4. 写入本地库成功后条目出现在列表顶部；失败则保留输入并提示，不得清空用户输入。

### 5.3 完成流程
1. 用户在列表勾选 → 记录"完成时间"。
2. **先落盘**：把该条已完成记录写入 Markdown 留底（规则见 §5.5）。
3. 留底写入成功后，才执行"移除/清理"动作；写入失败则**保留**该条并提示"已标记完成但留底失败"，且不得从活动列表消失。
4. 完成后短暂保留可撤销窗口（时长〔待确认〕；撤销即回滚状态与留底记录）。

> 不变式（与 D2 参数无关，建议作为硬性实现约束）：**写先于删**（write-before-delete）。任何情况下不允许"先从列表消失、留底后补"。

### 5.4 自动清理（D2〔待确认〕）

**清理时机**：〔待确认〕。候选枚举如下，**未选定，不得默认**：

| 候选 | 行为 | 对用户的影响 |
| --- | --- | --- |
| A | 完成瞬间清理 | 列表永远只有未完成项，最少视觉噪音；误勾即消失，只能靠撤销窗与归档找回 |
| B | 应用启动时清理 | 完成项在本次会话内可见，重启后消失；跨会话延迟 |
| C | 每日固定时刻清理 | 可当天回看已完成项；需常驻或下次启动补执行 |
| D | 手动清理 | 完全可控；需用户主动维护 |

- 无论选哪个：清理只作用于"已完成"条目，不得触碰未完成条目。
- 若选 B/C/D，需明确"已完成但未清理"的条目在列表中的呈现方式〔待确认〕。
- 清理动作与留底动作的先后顺序固定为：留底成功 → 清理（见 §5.3 不变式）。

### 5.5 Markdown 留底规则

用户已确认"完成后自动清理 + 本地 Markdown 留底"〔用户确认〕。以下是**规则参数**，全部〔待确认〕，实现前必须逐项定值：

| 参数 | 取值 |
| --- | --- |
| 留底触发点 | 待确认（完成时立即写 / 清理时批量写） |
| 留底文件位置 | 待确认（目录、文件名规则均未定） |
| 文件组织方式 | 待确认（单一累积文件追加 / 按日期分文件 / 按任务单独成文） |
| 单条记录格式 | 待确认（标题、完成时间、创建时间、备注、截止时间等字段的排版未定） |
| 是否保留完整历史 | 待确认（仅保留完成项 / 同时记录编辑与删除历史） |
| 编码 | 待确认（建议 UTF-8 需用户点头，不预设） |
| 去重键 | 待确认（是否以 id 防重复追加） |

**与参数无关、可直接实现的机制要求**〔拟议，建议列为硬约束〕：
1. **追加不覆盖**：留底写入只允许追加或新建文件，禁止重写既有历史内容。
2. **原子性**：单次写入要么完整可见，要么完全不存在（先写临时文件再替换，或带锁追加），不得产生半条记录。
3. **幂等**：同一条待办重复触发完成，不得产生两条留底。
4. **失败可见**：写入失败必须记录并在界面上提示，不得吞掉异常。
5. **人可读**：留底文件必须能被普通 Markdown 编辑器直接打开，不加密、不压缩、不加私有头。
6. **可回溯**：留底文件本身即视为可读备份；因此本项目**不额外做**备份功能（避免范围扩张），但须在文档中告知用户这一点。

### 5.6 异常与边界
- 磁盘满 / 只读 / 权限不足：留底失败 → 保留任务 → 持续提示，直到用户处理。
- 系统时间被回拨：完成时间以系统时间为准，但需在留底中保持单调性检查〔拟议〕。
- 任务在"已完成未清理"期间被删除：是否也写留底，属 D2 的"是否保留完整历史"范畴〔待确认〕。
- 多实例：单实例约束下不出现并发写；若未来放开，需文件锁。

## 6. 账号密码

### 6.1 记录字段〔拟议〕

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| id | 是 | 系统生成 |
| 名称 / 平台 | 是 | 如"某站后台" |
| 网址 | 否 | 纯文本，不做自动抓取标题/图标 |
| 账号 | 是 | 纯文本 |
| 密码 | 是 | **存储形态取决于 D1** |
| 备注 | 否 | 多行 |
| 创建 / 更新时间 | 是 | 自动 |

- 〔用户确认〕范围只到"账号密码"；**API Key、TOTP/两步验证密钥、银行卡、身份证件等不做**（与参考项目的"密钥"工作区划清界限）。
- 字段集〔拟议〕：D1 选型会改变"密码"字段的落盘形态与是否引入额外解锁字段，因此在 D1 确认前字段集不得冻结。

### 6.2 存储与保护方式（D1〔待确认〕）

用户提出的候选方向（原话口径：本地加密 / 系统凭据库 / 明文存储），三选一或组合，**未选定**：

| 候选 | 形态 | 带来的后果（决策依据） |
| --- | --- | --- |
| A 本地加密文件 | 启动/解锁时由主密码解锁后读写；加密算法、密钥派生方式、参数、盐与随机数管理、锁定策略**全部待确认** | 数据可整体拷走仍安全；忘记主密码即不可恢复；需定义解锁与自动锁定流程 |
| B 系统凭据库 / 系统加密绑定 | 交由操作系统按当前 Windows 用户保护；具体调用方式与是否逐条存储**待确认** | 无需记主密码；换机/换用户后可能读不出；与系统账户安全等级绑定 |
| C 明文存储 | 不做加密，仅存本地文件 | 实现最简；任何能读该文件的进程/人都能看到密码 |

**执行口径（硬性）**：
- 在 D1 定案前，**不得实现任何一种**，也不得写"暂按明文存、后面再加密"这类过渡实现（会产生真实明文数据）。
- 也不得因为参考项目使用"系统安全存储"就默认选 B。
- 允许先行的工作：模块导航占位、字段表单的**静态**布局草样（不接存储、不落盘）。
- 一旦选定，须同步补一份"数据模型 + 威胁边界"补充说明后再进入编码。

**D1 未决导致被阻塞的下游项**（均不得预设）：
- 密码字段的落盘形态（明文 / 密文 / 句柄引用）。
- 启动解锁流程与自动锁定策略。
- "复制密码到剪贴板"的行为与自动清空策略（是否做、多久清空）。
- 忘记口令的恢复路径与数据可迁移性。

### 6.3 能力边界（不承诺）
无论 D1 选哪个，本工具**不承诺**：抗键盘记录、抗内存取证、抗同权限恶意进程、抗截屏、加密云同步。这些不在本期范围，也不写进宣传口径。

## 7. 随笔

### 7.1 快速记录
- 入口：导航"随笔"→ 新建；或（若启用）快捷输入热键直达空白编辑器。
- 单篇为纯文本 / Markdown 源文本，不做富文本工具栏、不做双向链接。

### 7.2 编辑与保存
- 〔拟议〕**自动保存**：停止输入后短延时落盘 + 切换条目/隐藏窗口/退出前强制落盘；不设"保存"按钮。
- 保存失败必须提示并保留编辑缓冲。
- 保存策略（自动 / 手动）属〔拟议〕，需用户确认；不做则退化为手动保存。

### 7.3 列表与检索
- 列表：按更新时间倒序，显示标题（取首行）与时间。
- 检索：对标题与正文做本地全文关键字匹配（子串即可，不做分词/索引服务）。
- 操作：新建、编辑、删除（删除是否二次确认〔待确认〕）。
- 不做的：文件夹树、标签体系、重命名批量管理、导出。

### 7.4 文件格式（〔拟议〕）
- 每篇一个 Markdown 文件，文件名与元数据规则〔待确认〕；正文即用户输入原文。
- 若最终不在文件系统落 Markdown，则改为库内存储 + 单篇导出，属 D2/D5 范畴，不得自行决定。

## 8. 拟议技术选型（建议，非已确认选择）

> 本节全部为〔拟议〕。选型需用户确认后才可开工；以下仅提供判定条件。

### 8.1 候选与适用条件

| 候选 | 组成 | 适用条件 | 代价 |
| --- | --- | --- | --- |
| Tauri 2 | Rust 后端 + Web 前端（系统 WebView2） | 追求安装包小、内存低；团队接受 Rust；目标机为 Win10/11（WebView2 通常已具备，缺失需引导安装） | 生态与调试链不如 Electron 顺手；托盘/热键需选成熟插件 |
| .NET 8 + WPF（或 WinUI 3） | C# 原生桌面 | 只做 Windows；需要成熟托盘、全局热键、单实例、开机自启；可单文件发布 | 界面样式自绘成本高；跨平台为零 |
| Electron | Chromium + Node | 前端人力充足、要最快出可用 UI；能接受安装包与内存开销 | 体积大、常驻内存高，与"轻量常驻"目标冲突 |
| Flutter Desktop | Dart + 自绘引擎 | 未来有跨平台打算；接受自绘控件与插件成熟度差异 | 托盘/热键依赖第三方插件；安装包偏大 |

**判定顺序建议**（这不是结论）：先确认"是否只做 Windows"→ 再确认"是否可以接受 Rust / 是否必须有现成前端生态"→ 再按上表适用条件筛选。

### 8.2 与选型无关的共性技术点〔拟议〕
单实例互斥、系统托盘、全局热键注册与失败回退、开机自启（是否默认开启〔待确认〕）、窗口位置记忆、DPR 缩放适配、本地 SQLite 或等价嵌入式存储、Markdown 文件原子写。

## 11. 验收标准（可测）

**待办**
- 勾选完成后，留底文件出现对应记录；随后该条从列表消失（清理时机按 D2 定案后的口径验证）。
- 人为把留底目录设为只读：勾选完成后任务**不得**消失，界面出现失败提示。
- 同一条重复勾选不产生重复留底记录。

**随笔**
- 输入后隐藏窗口再唤出，内容不丢。
- 杀掉进程后重启，最后一段已落盘内容存在。

**账号密码**
- D1 定案前：模块内不出现任何可落盘的密码输入路径（防止产生明文数据）。
- D1 定案后：按补充的数据模型与威胁边界逐条验收（本文暂不写死）。

**界面**
- 全程序不存在贴顶居中的胶囊/留海式常驻控件（人工检查 + 截图留证）。
- 隐藏后任务栏无窗口、屏幕无遮挡；通过 D3 定案的唤出方式可恢复。
- 热键被占用时出现提示且托盘唤出可用。
